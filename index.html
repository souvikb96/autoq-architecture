Traceability Architecture: "The Test Case is the Centre"

Kyxo STLC Governance

In traditional setups, Playwright or Cypress tests are detached from business requirements. AutoQ establishes a permanent, bidirectional 5-stage traceability chain:

LEVEL 1 · BUSINESS EPIC
Feature / Module Epic
High-level business capability. Groups multiple related requirements for milestone releases.
e.g. KYX-EPIC-01: Checkout & Payments
LEVEL 2 · REQUIREMENT
Kyxo Requirement
User story with Given/When/Then acceptance criteria. The unit of product functionality.
e.g. REQ-890: Voucher 20% & 3DS
LEVEL 3 · THE CENTRE ⭐
AutoQ Test Case
Links upstream business requirement with downstream Git code. Tracks pass rate, history, and tags.
e.g. TC-104 (Smoke + Regression)
LEVEL 4 · GIT SCRIPT
Automation Code
Deterministic TypeScript code in Git. Version-controlled, reviewable via PR, $0 run token cost.
tests/e2e/checkout-promo.spec.ts
LEVEL 5 · EXECUTION & DEFECT
Sandbox & Triage
Ephemeral AKS run output. On failure, automatically triaged as bug or PR patch linked to REQ-890.
PR #892 (Self-heal) or JIRA-4091
